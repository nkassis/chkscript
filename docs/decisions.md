# Decisions

One line per deviation from a global default or other design choice, newest last: `YYYY-MM-DD — what was chosen — why`.

- 2026-10-26 — Python 3.11 floor instead of the template's 3.13 — wider install base for a CLI; nothing needs newer.
- 2026-10-26 — stdlib `logging` instead of structlog — a CLI whose logs are never shipped or queried (the global default's own exit).
- 2026-10-26 — `argparse` instead of Click — single command, no extra dependency.
- 2026-10-26 — no mypy; type hints enforced by Ruff `ANN` — matches the stack's Black plus Ruff hook contract.
- 2026-10-26 — `stacks/shell` not applied — `tests/fixtures/` and `tests/examples/` are intentionally bad Bash and its hook would block edits there.
- 2026-10-26 — tests stay in `tests/` — existing layout, which the template allows.
- 2026-10-26 — when both `X_API_KEY` and `X_API_KEY_FILE` are set, `X_API_KEY` wins — matches "env already set wins"; the spec does not say.
- 2026-10-26 — `CHKSCRIPT_DEPTH` above 4 is rejected (exit 3), not clamped — the spec says "capped at 4"; an explicit error beats a silent change.
- 2026-10-26 — default models: `claude-sonnet-5-5` when `ANTHROPIC_API_KEY` is set, else `ollama:gpt-oss:20b` — v0.1's `claude-sonnet-4-20250514` is retired (404); chosen by the maintainer during NIM-71. The Ollama default is resolved now but only usable once phase 3 wires the provider.
- 2026-10-28 — shellcheck codes SC1090 and SC1091 suppressed — both report that shellcheck cannot follow a `source`d file, which describes the scanning environment, not the script.
- 2026-10-28 — Semgrep rules live in `src/chkscript/rules/` rather than a top-level `rules/` — CLAUDE.md layout; hatch ships it as package data with no build config change.
- 2026-10-28 — rule `persistence-append` also fires on any write (not only `>>`) into cron and systemd unit directories, and on `crontab FILE` / `| crontab -` — creating a unit or crontab entry is the persistence the spec's "appends to crontab or systemd units" means.
- 2026-10-28 — rule `insecure-permissions` fires on `chmod 777` and setuid/setgid anywhere; only `chown root` is limited to paths under `$HOME` or `/tmp` — the spec's sentence is ambiguous, and a world-writable or setuid file is dangerous wherever it is.
- 2026-10-28 — rule `unverified-download` ignores comment lines when looking for a verifier — otherwise a comment such as `# verified with sha256sum` lowers a deterministic finding (threat model property 1).
- 2026-10-28 — `k3d-with-checksum.sh` is `unsafe`, not `warning` as in the spec's fixture table — its `rm -rf "$K3D_TMP_ROOT"` matches `rm-rf-variable`, and the maintainer chose to keep the rule as specified; the spec table needs updating.
- 2026-10-28 — a Semgrep crash, timeout or non-parse error is treated like a parse failure (a `chkscript` warning, `semgrep-failure`, and the regex rules run) — the floor must not silently disappear when the tool misbehaves.
- 2026-10-28 — "golden suite under the regex fallback alone" means Semgrep replaced by regex with shellcheck still running — without shellcheck `warnings_only.sh` cannot be a warning, and the warning tier is independent of the unsafe-tier engine.
- 2026-10-28 — `stacks/shell` stays unapplied after the NIM-95 installer corpus, rather than installed with `check-shell.sh` excluding `tests/corpus/` — every `.sh` here is a fixture, a verbatim third-party installer, or a hook copied from claude-code-patterns and linted there; there is no first-party shell to protect, and the hook has no exclude, so the alternative means forking it. Revisit if first-party shell appears.
- 2026-10-29 — both rule engines scan `ScriptBundle.rules_text`, where `preprocess` joins backslash-newline continuations onto the command's first line and leaves the consumed lines empty, instead of each engine seeing raw lines — Semgrep's `pattern-regex` saw raw text while the regex engine joined on its own, so a split command (`rm -rf \` + `"$DIR"`, even `cu\` + `rl ... | sh`) fired under one engine only, and scanning unjoined lines in both would let any rule be dodged by splitting a command. Cost: findings on a continued command report its first line, and a trailing `\` inside a heredoc or single quotes is joined too (over-reporting at worst). shellcheck and the model still get the original text.
- 2026-10-29 — Semgrep dropped as the static engine; `shfmt --to-json` replaces it, with the regex rules as fallback only — on the NIM-95 corpus Semgrep parses 5 of 11 real installers, and its rules fire on heredoc text and report `unverified-download` on the wrong line; shfmt parses all 11 and gives heredocs as data, not commands.
- 2026-10-29 — shfmt is an external tool on PATH, like shellcheck, not the `shfmt-py` wheel — `shfmt-py` is one maintainer's repackaging of the binary, a supply-chain trust a security tool should not take on. Cost: users install shfmt themselves, and an old distro package falls back to regex.
- 2026-10-29 — `capability` findings are severity `warning` and exit 1 — the exit code contract stays as it is; `capability` is a new category, not a new severity, so `--fail-on unsafe` keeps working unchanged.
- 2026-10-29 — disabling SELinux, a firewall or a security service, and setuid/setgid in a user-writable directory, stay unsafe rather than capability — no legitimate installer needs them, and both open the machine to anyone, not just the installer's author.
- 2026-10-29 — `unverified-download` becomes a capability, not unsafe — a checksum fetched from the same server over the same connection adds little, because whoever can swap the binary can swap the checksum; real trust comes from a signature checked against a key obtained elsewhere or a checksum pinned in the script. `http://` and disabled TLS stay unsafe.
- 2026-10-29 — `rm-rf-variable` is split: `rm -rf` on an unguarded `"$VAR/..."` or an unquoted variable is unsafe, on a quoted or guarded variable it is a capability — supersedes the 2026-10-28 `k3d-with-checksum.sh` entry that kept the rule as specified; under the split both k3d installers are `warning`, as the original fixture table said.
- 2026-10-29 — syntax-tree rule findings use `source: shfmt` — names the tool that produced the tree, as `shellcheck` does; the spec did not say (NIM-121).
- 2026-10-29 — chkscript's coverage notices (shfmt parse failure, LLM layer did not run) are `category: lint` — every finding needs a category, and a notice is neither a capability nor unsafe; the spec did not say (NIM-121).
- 2026-10-29 — minimum shfmt is v3.5.0 — believed to be the first release with the long `--to-json` flag (earlier releases spell it `-tojson`); unverified, NIM-122 confirms it (NIM-121).
- 2026-10-29 — a model raise of a capability finding to unsafe with no reason is ignored — the issue requires a reason, and a reasonless raise cannot be shown to the user; the spec did not say what happens without one (NIM-121).
- 2026-10-29 — `pydantic-ai-slim[anthropic,openai]` is a required dependency for now; making the provider extras optional is deferred to the release phase — until chkscript is on PyPI it installs from git, where an install without extras would have no provider at all (NIM-134).
- 2026-10-29 — a model finding that names a static finding's `(rule_id, line)` is kept only as a reasoned raise of a capability to unsafe; any other restatement is dropped rather than merged as explanation — the static finding is already reported, and merging model text into it would let the model reword a finding it may not re-rate (NIM-134).
- 2026-10-29 — model findings with no static counterpart get rule id `llm.<id>` (or none), and a line outside the script becomes null — the prefix means a model finding can never merge into, and so never stand in for, a static rule (NIM-134).
- 2026-10-29 — model output budget is 4096 tokens plus 32 per script line, capped at 32,000 — enough for findings on a long installer, below current hosted output limits; truncation is an error either way (NIM-134).
- 2026-10-29 — when the model call fails, the report is `mode: static-only` and carries a `chkscript` `llm-not-run` lint warning, so a script with no static findings exits 1 — the mode says what actually ran, and a silent exit 0 would hide that the intent layer is missing (NIM-134).
- 2026-10-29 — a floor-guard violation after the merge exits 3 with an internal error and prints no report — a merge bug must fail loudly, and printing a report that may have lowered a finding is the failure the guard exists to stop (NIM-134).
- 2026-10-29 — the Ollama probe is a 0.5 s `GET <OLLAMA_BASE_URL minus /v1>/api/tags` with stdlib `urllib`, and a reachable Ollama selects `ollama:gpt-oss:20b` whether or not it is pulled (a missing model is an LLM failure, reported as above); `OLLAMA_BASE_URL` is set to its default in-process when an Ollama model is chosen — no new dependency; the spec's installed-model fallback is left for later (NIM-134).
- 2026-10-29 — the leaves-the-box host is the constructed pydantic-ai model's `base_url`, so it follows `ANTHROPIC_BASE_URL`, `OPENAI_BASE_URL` and `OLLAMA_BASE_URL` with no provider table in chkscript; loopback is `localhost` or a loopback IP (NIM-134).
- 2026-10-29 — `temperature=0` is omitted when pydantic-ai's profile says the Anthropic model rejects sampling settings — pydantic-ai would drop it anyway, with a warning on stderr (NIM-134).
- 2026-10-29 — model fixtures' expected outcomes live in `tests/test_live.py`, not the static golden suite, and `--run-live` uses Ollama unless `CHKSCRIPT_MODEL` is set, even with `ANTHROPIC_API_KEY` present — the golden suite is static-only and owned by NIM-122; the spec names Ollama as the live default (NIM-134).
- 2026-10-29 — README gives no `uv tool` line for shellcheck, only for semgrep — the only `uv tool` route is `shellcheck-py`, a third-party repackaging of the binary, the same supply-chain trust the shfmt entry above declines (NIM-114).
- 2026-10-30 — the CLI catch-all for an unexpected exception prints only the exception type (`Error: Unexpected error (AttributeError)`), not its message — an arbitrary exception's text can span lines or carry request or input data, and secrets must never reach errors; the issue said one line but not what it holds (NIM-138).
- 2026-11-01 — secret detection has no entropy scanning: known formats plus a name-based assignment heuristic only — entropy checks flag checksums, commit ids and base64 data all over real installers, and a missed secret costs less here than a noisy finding on every installer; verified-secret scanning is pre-commit's job (NIM-151).
- 2026-11-01 — no `--no-redact` flag; masking is always on — a credential in a snippet leaks into CI logs with or without a model, and no use case for unmasked output has come up (NIM-151).
- 2026-11-01 — values first seen on the same line share one `hardcoded-secret` finding listing every placeholder — findings merge on `(file, line, rule_id)`, so two would collapse anyway; making it explicit keeps both placeholders in the message (NIM-151).
- 2026-11-01 — the `hardcoded-secret` description names the placeholder (`Hardcoded credential [SECRET-1:github-token] on lines 4, 5: ...`) — the terminal shows a warning's snippet only with `-v`, and the issue wants the masked value visible on the finding (NIM-151).
- 2026-11-01 — the assignment heuristic skips URLs, paths (`/`, `~/`, `./`), expansions and placeholder-looking values (`your-…`, `…-here`, `changeme`, `example`, `<…>`, one repeated character) — `TOKEN_URL=https://…` and `.env.example`-style text name where a secret lives, not the secret; the issue listed only `your-key-here` (NIM-151).
- 2026-11-01 — an AWS secret access key is detected only as 40 base64 characters with both cases, and only when the script also holds an `AKIA` key id — the issue says "paired"; requiring both cases keeps 40-character hex SHA-1s out (NIM-151).
- 2026-11-01 — the do-not-share notice is logged with the other stderr notices; there is no `--quiet` flag yet, so it follows `--quiet` when that lands (NIM-151).
- 2026-11-01 — the footprint summary and the model's justification never affect a finding's category or severity, the merge, the floor check or the exit code — the verdict answers "is this hostile or broken?" and the footprint "is this proportionate?"; letting a `needed` lower anything would hand the model a way to argue down the floor, and a raise already has its own path with its own reason (NIM-161).
- 2026-11-01 — the footprint summary is computed by chkscript from findings and recorded downloads; justification (purpose and assessments) is the model's — the summary must hold in `--static-only` and be pinnable in `expected.toml`; proportionality is the judgment the model is good at (NIM-161).
- 2026-11-01 — absence ("No other changes found") is stated only with full static coverage and no unresolved dynamic code; otherwise the report says coverage was reduced or names the unresolved line — an absence is a claim, and a quieter report must never be what an evasive script earns (NIM-161).
- 2026-11-01 — the purpose is labeled `claimed` ("as the script describes itself") unless the user gave it with `--expect` — when the model infers the purpose from the script, the script's author wrote the premise the capabilities are judged against (NIM-161).
- 2026-11-01 — a suggested alternative is kept only with an `alternative_line` in the same file; otherwise it is dropped and the verdict stays — advice the script does not support is advice the user cannot follow. chkscript checks the line exists, not that the model read it right (NIM-161).
- 2026-11-01 — adding a user to `docker`, `lxd`, `libvirt` or `disk` is the capability `root-equivalent-group` in the `trust` group; `sudo` and `wheel` stay with the unsafe `rogue-account` (NIM-110) — the first four are root in practice but routine for container and VM tooling; no installer needs to grant `sudo` (NIM-161).
- 2026-11-01 — `purpose_source` is set by chkscript, not taken from the model's output, and with `--expect` the purpose is the user's text verbatim — the label is the defense against a self-justifying script, so the model must not be able to choose it; the issue did not say who sets it (NIM-161).
- 2026-11-01 — a download whose host is not a constant adds `(unresolved)` to `network_hosts` — otherwise a variable-built URL makes the `NEEDS` line report fewer hosts; the issue did not say (NIM-161).
- 2026-11-01 — when the absence claim cannot be backed, a `privilege` of `user` and a `persistence` of false become null ("root not ruled out", "persistence not ruled out") — "no persistent changes" is the same kind of claim as the absence line and needs the same backing; the issue did not say (NIM-161).
- 2026-11-01 — the footprint covers every file in the run, generated and fetched children included — a generated child that installs a service is still the machine's footprint; the issue did not say (NIM-161).
- 2026-11-01 — findings carry `group` in JSON (null outside the capability tier), kept after a model raise — JSON consumers need the same grouping the terminal report uses, and a raised finding still counts toward the footprint; the issue named only the top-level fields (NIM-161).
- 2026-11-01 — `hardcoded-secret` (NIM-151) is in the `other` group — it is a capability, and every capability rule needs a group; it is not a change the script makes to the machine (NIM-161).
- 2026-11-12 — minimum shfmt is v3.14.0, not v3.5.0 — v3.14.0 is the first release whose `--to-json` writes operators as strings (mvdan/sh#1321, in its release notes); v3.5.0 only added the long flag. Supersedes the 2026-10-29 entry; an older tree is also rejected at decode time (NIM-122).
- 2026-11-12 — findings in a generated child file carry `generated: true` and `parent_line` (the parent line that writes it); `file` is the path as written, or its source text (`${KILLALL_K3S_SH}` as `$KILLALL_K3S_SH`) when it is not a constant — the issue asked for the child path and a reference to the parent line, not the field names (NIM-122).
- 2026-11-12 — a constant resolves only at uses after its first assignment in file order, and a name bound by `read`, `for`, `getopts`, `printf -v`, `${X:=}`, `+=`, a nameref, an indexed assignment or an `X=` inside `eval` is unknown — so an environment value can never pass as a constant (NIM-122).
- 2026-11-12 — a function is inlined at each call when its body reads its positional parameters, not only when it runs `"$@"`; an inlined command is kept only when it read the call's arguments or a local built from them, and is reported where its command word was written (the call line for a `"$@"` pass-through, the body line otherwise) — catches nvm's `nvm_download` and rustup's `downloader` without duplicating every command of `main "$@"` at the last line (NIM-122).
- 2026-11-12 — a function whose body runs a command it could not resolve, called with a literal command name, is also read as a wrapper of its arguments, as root when its body contains `sudo` or `doas` — k3d's `runAsRoot` builds `CMD="sudo $*"` and runs `$CMD`; over-reading is the cautious direction (NIM-122).
- 2026-11-12 — an unknown lone unquoted variable in command position (`$SUDO cmd ...`) is read both as the command and as an empty or wrapper prefix — either may be true, and the second keeps `cmd` visible to the rules (NIM-122).
- 2026-11-12 — `xargs` is stripped as a wrapper alongside the six the issue lists — it runs its arguments as a command, and k3s's killall script runs `rm -rf "$0"` through `xargs ... sh -c` (NIM-122).
- 2026-11-12 — a download is tied to a later path by the same text or value, the same basename, an archive or checksum suffix (`$exe.zip` and `$exe`, `t.sha256` and `t`), or a `mv`/`cp`; a check-mode verifier whose sums file ties to no download counts for every download, as before (NIM-122).
- 2026-11-12 — an unknown pipe receiver, or a bare `sudo`/`doas` receiver, is judged a shell; an `rm -rf` operand built from an expansion fires when it is unknown or can be empty or `/`, and not when it resolves to a literal path — the spec's "judged as the dangerous case" for unknown values (NIM-122).
- 2026-11-12 — the `unverified-download` message now ends "check of that file" instead of "anywhere in the script" — the rule is judged per file now, and the old wording would be false (NIM-122).
- 2026-11-12 — the regex fallback is widened where the tree resolves what the text does not show (a variable run as a command or as a pipe receiver, `cp`/`mv`/`install`/`ln`/`sed -i` targets, extra words before a disabled service) and judges `unverified-download` per file by text — so it stays a superset of the engine; its extra hits are recorded as regex-only corpus entries (NIM-122).
- 2026-11-12 — embedded code shfmt cannot parse (a `bash -c` string, a heredoc fed to a shell) gets the regex rules at its own lines, even in a file shfmt parsed — otherwise an unparseable snippet would drop the floor for that code; this is the one place the regex rules run on a parsed file (NIM-122).
- 2026-11-12 — a run, install or `chmod +x` of a written path is attributed to the nearest preceding write of a tied path, else the first one after — k3s writes `$FILE_K3S_SERVICE` twice (a systemd unit, then an OpenRC script) and chmods only the second; scanning the unit as shell was noise (NIM-122).
- 2026-11-12 — generated files are scanned to a depth of 3, through the full static layer (shellcheck included), and only by the syntax-tree engine; the regex fallback sees the heredoc in place — a child exists only where there is a tree (NIM-122).
- 2026-11-12 — "nearby" in the fallback-superset test is within 2 lines, and a child finding is compared at the parent line its child line comes from — the issue said "per line or nearby"; today every corpus and fixture finding matches on the exact line (NIM-122).
- 2026-11-12 — `expected.toml` gains an optional `file` per entry and `<engine>_max_severity` per installer, and a "true-positive" now includes code run later from a generated file — Homebrew is `safe` under shfmt and `unsafe` under regex, and k3s's child findings need their own file (NIM-122).
- 2026-11-14 — a word resolved from a constant or a function local stays marked as an expansion, and a flag is read from a known value — knowing `DIR=/` must not turn `rm -rf "$DIR"` into a literal path, nor `eval "$cmd"` into literal code; `FLAGS=-fsSL; curl $FLAGS` still parses as flags (NIM-122 review).
- 2026-11-14 — `local`, and `declare`/`typeset` without `-g` inside a function, make the name unknown outside that function; inlined calls still resolve it through the call's locals — otherwise an uncalled function's local proves a global safe (NIM-122 review).
- 2026-11-14 — embedded code (a `-c` string, a heredoc or here-string fed to a shell) resolves names it assigns itself at its own positions, and every other name from the entry file as before — outer values stay visible because the outer shell expands unquoted heredocs and "..." strings first; a non-exported variable not reaching a `bash -c` child is not modeled (NIM-122 review).
- 2026-11-14 — a `<<<` here-string fed to `sh`/`bash`/`zsh` or `source /dev/stdin` is code, like a heredoc; `cat <<< ... | sh` is left to the regex fallback — the issue listed heredocs only, and the review showed the gap (NIM-122 review).
- 2026-11-14 — a statement with only redirects or assignments is kept in the model as a command with an empty argv when a redirect writes — `>/etc/shadow` truncates the file; no rule treats an empty argv as a command to run (NIM-122 review).
